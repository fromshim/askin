# askin 데스크톱 앱 화면

역할을 나눈다. **"왜 이렇게 생겼나"는 [`desktop/design-concept.md`](./design-concept.md) 가 맡는다.**
이 문서는 어떤 화면이 있고, 화면 사이를 어떻게 오가고, 화면마다 무슨 데이터가 있어야 하는지만
다룬다. 같은 말을 design-concept.md 와 두 번 쓰지 않는다.

화면 열셋의 이름과 배치는 [`desktop/canvas/canvas.json`](./canvas/canvas.json) 이 정본이다.
목업을 뽑는 코드는 [`desktop/canvas/gen.py`](./canvas/gen.py) 다. 실행 가능한 기준 화면은
[`desktop/askin-desktop-prototype.html`](./askin-desktop-prototype.html) 이다. 이 문서에 적힌
화면 이름·조건·문구는 세 파일을 실제로 열어 확인한 것이다.

## 0. 지금 어디까지 만들었나

2026-09-13 기준. 앱은 `npm run desktop` 으로 뜬다(`desktop/app/`). 아래 표들의 `뽑나` 열은
CLI 층이 그 값을 낼 수 있는지를, `화면에 있나` 열은 앱이 실제로 그리는지를 말한다. 둘은 다른
질문이다 — 뽑히는데 아직 안 그리는 것이 있다.

**그리는 것**

- 사이드바 프로젝트 목록. 사용자가 고른 것만 담는다(`desktop/app/projects.mjs`,
  `~/.harness-bro/projects.json`). 추가·제거가 된다. 기본은 빈 목록이다
- 내 하네스 섹션. 요약 띠 다섯 칸(`inventory()`, `src/coach.mjs`) 위에 하네스 연결 그래프를
  240px 로 그린다. `src/graph.mjs` 의 `harnessGraph()` 가 노드·엣지를 내고 Sigma 가 그린다.
  노드를 누르면 팝오버가 뜬다. 줌 세 단계가 있다
- 분석 레포트. 아쉬운 점 카드(반복 → 규칙 → 깨진 것 층, 두 열, `지시서 복사`·`문제 아님`
  버튼, `cards()`/`handoff()`, `src/coach.mjs`) + 세부 분석 카드 여덟(규칙·모델 / 관찰값 /
  캐싱 / 훅 / 반복 행동 / 깨진 링크와 정의 / 한도 / 무엇을 봤나, 도구 배지)
- 창은 1680×1080 으로 뜨고 사이드바·채팅 칸 폭을 드래그로 바꾼다(폭은 `localStorage` 에 남는다)
- macOS 패키징. `npm run dist`(electron-builder --mac)로 .dmg/.zip(arm64, 서명 없음)이
  나온다(`electron-builder.yml`). `npm run pack` 은 폴더만(`--dir`) 만든다

**아직 자리만 있는 것**

현재 세션 패널, 채팅 패널. 둘 다 "아직 안 만듦"이 적혀 있다.

**아직 없는 것**

Config·Scanning 화면, 레포트 이전/다음 탐색, 세션 접기/펼치기 토글.

**레포트를 다시 설계한(2026-09-04) 것을 구현했다(2026-09-13).** 지금 앱은 findings·규칙
위반 축을 반복 → 규칙 → 깨진 것 층으로 묶은 **아쉬운 점 카드**로, 축을 주제별 카드 여덟으로,
그래프 위에 요약 띠를 더한 **내 하네스** 섹션으로 그린다(`src/coach.mjs`, `desktop/app/main.mjs`·
`renderer.mjs`·`index.html`). 아직 목업에만 남은 것은 채팅 패널, 세션 패널, 새 축 셋(캐시
읽기 없는 턴 · 한도 · Codex 토큰 합치기), 반복 명령 카드, 비용 차액, 레포트 기간 헤더의
이전/다음이다.

**Codex 를 같이 본다.** `src/codex.mjs` 가 `~/.codex/sessions` 를 읽고 `harnessGraph(repo,
{ codex: true })` 가 그 사실을 같은 그래프에 섞는다(앱은 늘 켠다). 축에는 안 섞는다 —
`chore-model` 이 haiku 가 아닌 모델을 위반으로 보고 `model-explicit` 은 `~/.claude/CLAUDE.md`
를 근거로 삼아서, Codex 를 넣으면 전부 위반이 된다.

## 1. 화면 목록

`Main`·`Expanded`·`Empty`·`Config`·`Scanning`·`Dark`·`FirstRun`·`NoHarness`·`Narrow` 아홉은
사이드바·메인·채팅을 다 갖춘 앱 창이다(`ask_window()`). `Zoom`·`NodePick`·`Details`·`Handoff`
넷은 그렇지 않다. `gen.py` 가 이 넷을 만들 때는 `ask_window()` 를 안 쓰고 화면 일부만
`ask-main-panel` 로 감싸 확대해서 그린다. `Zoom`·`NodePick`·`Details` 는 그래프·세부 분석
컴포넌트의 상태 사양이고, `Handoff` 는 아쉬운 점 카드에서 채팅으로 넘어가는 흐름의 확대 컷이다.
넷 다 앱에 실재하는 별도 화면이 아니다.

page-1 은 Main → Details → Handoff → Expanded → Empty → Config → Scanning 순이다. 레포트 흐름이 첫
페이지에서 한눈에 보이게 Details·Handoff 를 Main 오른쪽에 뒀다. 창 목업은 앱 기본 창과 같은 1680 폭이다
(`canvas.json`). page-2 는 그래프 컴포넌트(Zoom·NodePick), page-3 은 상태와 환경 화면이다.
`data-fold="1080"` 이 접힌 선이다. Main·Expanded 는 1680×1080 창의 아래끝을 점선으로 보여준다.

| 화면 | 한 줄 설명 | 나타나는 조건 |
|---|---|---|
| Main | 현재 세션(접힘) + 내 하네스(요약 띠·그래프) + 분석 레포트(아쉬운 점 카드·세부 분석)가 같이 보이는 기본 화면 | 프로젝트를 선택했고, 이 프로젝트에 레포트가 1개 이상 있다 |
| Expanded | 현재 세션을 펼쳐 세션 행(turn 수·마지막 기록·도는 중 여부)과 호출 흐름이 보이는 화면 | Main 과 같은 전제 + 사용자가 "현재 세션 펼치기"를 눌렀다 |
| Empty | 프로젝트를 방금 추가해 레포트가 아직 없는 화면 | 이 프로젝트에 저장된 레포트가 0개다 |
| Config | "무엇을 분석할까요?" 기간·범위 설정 폼 | Empty 나 이미 있는 레포트 화면에서 "분석하기"를 눌렀다 |
| Scanning | 분석 중, 고정 높이 진행 상태 | "분석 시작"을 누른 뒤 결과가 나오기 전까지 |
| Zoom | 그래프 줌 세 단계(멀리/중간/가까이)의 라벨 밀도 비교 | 화면이 아니라 그래프 컴포넌트의 줌 사양. Main 안에서 `−`/`+` 로 도달 |
| NodePick | 그래프에서 노드를 고른 상태(노드 위 팝오버) + 키보드용 대체 목록 | 화면이 아니라 그래프 컴포넌트의 선택 사양. Main 안에서 노드를 클릭하면 도달 |
| Details | "세부 분석 펼치기"를 연 상태 + 판정 불가 표시. 그래프는 안 담는다(그래프는 시간 축이 레포트와 달라 따로 본다) | 화면이 아니라 레포트 세부 분석 컴포넌트의 펼침 사양. Main/Expanded 안에서 도달 |
| Handoff | 2층(규칙) 아쉬운 점 카드 + 두 선택지 + 채팅 첫 메시지 + "채팅으로 같이 가는 것" 목록 | 화면이 아니라 카드의 `채팅에서 고치기` 클릭 이후 흐름의 확대 컷. Main 안에서 도달 |
| FirstRun | 프로젝트를 하나도 추가하지 않은 첫 실행 | 등록된 프로젝트가 0개다 |
| NoHarness | 선택한 저장소에 하네스 문서가 없을 때 | 이 저장소에 CLAUDE.md·AGENTS.md·`.claude/agents/*.md` 가 하나도 없다 |
| Narrow | 창 폭이 좁을 때 | 뷰포트가 680px 이하다(프로토타입 CSS `max-width:680px` 기준) |
| Dark | Main 의 다크 모드 | 시스템이 다크 모드다. 데이터는 Main 과 같고 테마만 다르다 |

Handoff 는 이 저장소가 아니라 korean-tone 저장소 실측(2026-09-04)으로 그렸다. 이 저장소에는
규칙 위반이 0건이라 2층 카드가 안 나온다.

## 2. 화면 간 이동

```
프로젝트 0개                → FirstRun → "프로젝트 추가" → Empty
프로젝트 있음, 레포트 0개    → Empty → "분석하기" → Config → "분석 시작" → Scanning → 완료 → Main
프로젝트 있음, 레포트 있음    → Main (접힌 게 기본. 마지막으로 펼쳐뒀다면 Expanded)
```

**지금 앱은 이 흐름을 안 거친다.** 저장된 레포트를 꺼내 보는 개념이 없어서 Empty·Config·
Scanning 이 통째로 빠졌다. 실제로는 이렇다.

```
프로젝트 0개                → FirstRun → "＋ 프로젝트 추가" → 폴더 고르기 → 아래로
프로젝트를 고름             → 그래프를 먼저 그린다 → 레포트를 재서 뒤이어 채운다 → Main
```

기간을 고르는 단계가 없어 늘 전체 기간이다. 이 차이를 메울지, 지금 흐름을 정본으로 삼을지는
아직 안 정했다.

같은 화면 안에서 body 만 바뀌는 이동(화면을 새로 그리지 않는다):

- Main ↔ Expanded: "현재 세션 접기/펼치기" 토글. 접힌 Main 이 기본이다(도는 세션은 실측으로
  보통 0~5개다)
- Main 안에서 `‹`/`›`: 이전/다음 레포트로 기간만 바뀐다(그래프·카드는 그 레포트 것으로 다시 그려야
  하는데, 4-F 절에서 보듯 지금은 축 숫자만 남아 있어 못 그린다)
- Main 안에서 그래프 노드 클릭: 그 노드 위(그래프 경계에 걸리면 아래로 뒤집혀)에 팝오버가 뜬다.
  다른 곳을 클릭하거나 Esc 를 누르면 닫힌다(NodePick 은 이 상태의 확대 컷)
- Main 안에서 그래프 `−`/`+`: 줌 단계가 바뀐다(Zoom 은 이 세 단계의 확대 컷)
- Main 안에서 "세부 분석 펼치기": 같은 화면 안에서 섹션이 펼쳐진다(Details 는 펼친 상태의 확대 컷)
- 사이드바에서 하네스 문서가 없는 프로젝트로 전환 → NoHarness
- 뷰포트를 680px 이하로 줄임 → Narrow(별도 화면이 아니라 반응형 상태)
- 시스템 다크 모드 → Dark(별도 화면이 아니라 테마 상태)

아쉬운 점 카드의 `채팅에서 고치기`, 그래프 노드 상세의 `솔루션 채팅`은 같은 흐름으로 모인다.
`Handoff.dc.html` 이 이 상태의 확대 컷이다(2층 카드 예시, 두 선택지, 채팅 첫 메시지, "채팅으로
같이 가는 것" 목록까지 담는다. 4.0-G 참고).

```
채팅에서 고치기 / 솔루션 채팅
        │
        ▼
  두 선택지: [현재 채팅에 넣기]  [새 채팅으로 시작]
        │                       │
        ▼                       ▼
  지금 대화에 이어서            기존 대화는 로컬 탭으로 남고
  분석 결과가 다음 메시지로      분석 결과를 첫 문맥으로 새 세션 시작
        └──────────┬──────────┘
                   ▼
              채팅 패널로 이동
```

## 3. 상태 분기

Main 이라는 하나의 틀 안에서 body 값이 바뀌는 경우가 대부분이다. 새 화면을 만드는 대신 같은 틀
안에서 다르게 채운다.

- **프로젝트가 없을 때** → FirstRun. 사이드바에 프로젝트 목록 자체가 없다(`sidebar_minimal()`)
- **이 프로젝트에 레포트가 없을 때** → Empty. 세션 패널은 있어도 비어 있을 수 있다(count=0)
- **하네스 문서가 없을 때** → NoHarness. 저장소 축 일부가 판정 불가로 바뀐다. 정확한 범위는
  4-10절에서 다룬다. 목업 문구가 가리키는 세 축 중 하나는 실제로는 다른 이유로 판정 불가가 된다
- **도는 세션이 0개일 때** → 세션 패널이 빈 문구(`SESSION_EMPTY_BODY`)로 바뀐다. Empty·Config·
  Scanning·NoHarness 는 전부 이 빈 상태를 쓴다
- **판정 불가일 때** → Details 의 "못 잰 축" 목록, NoHarness 의 안내 문구가 이 상태를 담당한다.
  0% 로 뭉개지 않는다
- **창이 좁을 때(≤680px)** → Narrow. 사이드바가 위로 올라가 2열 그리드가 된다(아이콘 레일이
  아니다). `canvas.json` 의 `note-narrow` 주석이 design-concept.md 와 프로토타입이 여기서
  어긋난다고 이미 적어뒀다
- **다크 모드일 때** → Dark. `color-scheme: dark` 로 `light-dark()` 토큰만 바뀐다

## 4. 각 화면이 필요로 하는 데이터

먼저 여러 화면이 공유하는 데이터 블록 일곱 개를 한 번에 정리한다(4.0). 화면별 절(4.1~4.12)은
이 블록 중 무엇을 쓰는지와, 그 화면만의 항목을 표로 낸다.

`앱이 지금 뽑나` 열은 `O`(뽑는다) / `X`(안 뽑는다) / `일부`(원자료는 있지만 조립·집계가 없거나
불완전하다) 셋 중 하나다.

### 4.0 공용 데이터 블록

#### A. 사이드바 프로젝트 목록

| 필요한 값 | 뽑나 | 화면에 있나 | 어디서 |
|---|---|---|---|
| 등록된 프로젝트(디렉터리) 목록 | O | O | `listProjectPaths()`, `desktop/app/projects.mjs`. 사용자가 고른 경로만 `~/.harness-bro/projects.json` 에 담는다. 전에는 등록 개념 자체가 없어 X 였다 |
| 프로젝트 이름(사람이 읽는 실제 경로) | O | O | 목록이 절대경로를 담으니 basename 이면 된다. `projectSlug()` 의 역함수는 여전히 없지만 필요가 없어졌다 |
| 프로젝트별 "하네스 문서 있음" 표시 | O | O | `harnessDocs(repo).length > 0`, `src/refs.mjs:243` |
| 선택된 프로젝트 표시 | 해당 없음 | O | 앱 UI 상태다. `markActiveProject()`, `desktop/app/renderer.mjs` |
| 프로젝트 추가·제거 | O | O | `projects:add` 는 메인 프로세스가 폴더 고르기 창을 연다(`dialog.showOpenDialog`). 제거는 목록에서만 빼고 폴더는 안 건드린다 |

**한 번이라도 연 디렉터리를 다 보여주면 안 된다.** 전에는 `~/.claude.json` 의 projects 키를
통째로 읽었는데, 저장소·워크트리·임시 디렉터리를 안 가려서 목록이 아니라 이력이 됐다.
Codex 만 쓴 프로젝트는 거기 아예 없다(Codex 전사 기준 31곳 중 여럿이 그렇다).

#### B. 현재 세션 패널

세션 패널은 아직 "아직 안 만듦" 자리표시자다. 아래는 만들 때 필요한 값이다.

| 필요한 값 | 뽑나 | 화면에 있나 | 어디서 |
|---|---|---|---|
| 이 프로젝트에서 지금(또는 최근) 도는 세션 목록 | X | X | 원자료(`turns`·`mtime`·`startedAt`·`endedAt`)는 `readSession()`(scan.mjs:271)에 다 있다. `buildReport()`(report.mjs:268)가 세션 로우를 리포트로 안 내보낸다. 축 계산에만 내부적으로 쓴다 |
| 세션 하나의 turn 수 / 마지막 기록 시각 | X (buildReport 경로) | X | 위와 같음. `scan.mjs` 를 직접 부르면 얻을 수 있다(`sessions()`, scan.mjs:189) |

#### D. 아쉬운 점 카드

목업이 카드의 성격을 바꿨다. 기존은 자연어 취약점 서술 하나를 순위 없이 늘어놓았다. 새 설계는
층을 **고정 순서**로 둔다: 반복(손으로 되풀이한 일) → 규칙(적어둔 규칙을 안 지킨 것) →
깨진 것(문서·링크가 가리키는데 없는 것). 층 안에서도 순위를 계산하지 않는다. 같은 종류·같은
범위는 한 카드로 묶는다(심링크 3건이 카드 석 장이던 것을 한 장으로, `weak_card()`, gen.py:508).

카드 한 장의 구성은 다섯 줄을 안 넘는다: 칩(층·범위·확실/확인 필요) → 제목(사실 한 문장) →
근거(원문) → 종류별 주의(있으면) → 추천 한 줄 → 행동 버튼 둘(`지시서 복사`, `문제 아님`).
목업의 `채팅에서 고치기`·라디오 선택지는 없앴다. 채팅 패널이 아직 없어서, 대신 지시서를
클립보드에 담아 사용자가 직접 붙여넣게 한다(`coachHandoff()`, `desktop/app/renderer.mjs`).

| 필요한 값 | 뽑나 | 화면에 있나 | 어디서 |
|---|---|---|---|
| **깨진 것** 카드의 재료 | O | O | `findings()`(`fix.mjs:38`)가 다섯 종류를 내고 `cards()`(`src/coach.mjs`)가 종류·범위로 묶는다. 실측(이 저장소, 2026-09-13): 죽은 경로 1건(전역 CLAUDE.md:56, 확인 필요) → 카드 1장. 전역 스킬 심링크 3건은 9월 4일 이후 고쳐져 0건이다 |

#### E. 세부 분석 섹션

목업의 네 서술 섹션(호출 흐름·컨텍스트 사용·도구 연결·분석 근거)을 걷고 **주제별 카드 여덟**으로
다시 짰다: 규칙·모델 / 관찰값(위임과 세션) / 캐싱 / 훅 / 반복 행동 / 깨진 링크와 정의 / 한도 /
무엇을 봤나(`DETAILS_SECTIONS_DEFAULT`, gen.py:664-752). 카드 제목 옆에 그 값이 어느 도구
기록에서 왔는지 배지를 단다(Claude · Codex, `src_badge()`, gen.py:633). 0건도 흐리게 그대로
적는다. "잡을 수 있는 증상이 무엇인지"가 이 카드의 질문이라서다. 위 아쉬운 점 카드로 올라간
증상에는 "아쉬운 점" 칩이 붙는다(`count_row(..., up=True)`, gen.py:637-648).

**만들었다.** `desktop/app/main.mjs` 의 `details` 배열이 여덟 칸을 조립하고 `renderer.mjs` 의
`detailCardEl()` 이 그린다. 배지는 `card.sources` 를 `ask-src` 클래스로 그린다(글자만, gen.py
의 SVG 로고 자산은 아직 없다). 준수율 값 표기가 `0/24` 에서 "N건 중 M건 위반 · P%" + 미터로
바뀌었다(`ruleRowEl()`/`ruleDetailRow()`).

기존 축(준수율 5개 + 관찰값 8개 = 13개, `report.compliance`/`report.observation`)의 뽑나는
그대로 O 다. 여덟 카드는 이 13개를 주제별로 재배치한 것뿐이다. 카드마다 새로 필요해진 축이
셋 있고, 셋 다 아직 X 다. 카드 안에서 그 축의 줄만 없거나(규칙·모델 차액, 캐싱 신규 턴), 카드
전체가 비어 "아직 재지 않아요"로 뜬다(반복 행동, 한도). `detailCardEl()` 이 `rows.length === 0`
일 때 이 문구를 낸다.

### 4.12 Dark

fable 2 · haiku 1, 16.8일 차액 $1.11 → 월 $2)이다. 이 저장소에는 규칙 위반이 없어 2층 카드가 안
나온다. 데이터 요구는 4.0-D(규칙 카드)와 4.0-G(같이 가는 것) 표에 있다.

## 5. 아직 못 만드는 화면

우선순위는 매기지 않는다. 화면별로 무엇을 먼저 만들어야 살아나는지만 적는다.
0절에 지금 무엇이 그려지는지 있다.

**그래프는 만들었다.** `harnessGraph()` 가 노드·엣지를 내고 Sigma 가 그린다. 이 절에서 전에
"그래프 조립이 선행돼야 한다"고 적었던 것은 전부 풀렸다.

**스킬 쪽 결함은 절반 고쳤다.** `skillIndex()` 가 `<플러그인>:<스킬>` 로도 찾고 스킬
하나짜리 플러그인도 잡는다. 실제로 불린 25종 중 찾는 것이 7 → 14 가 됐다. 남은 절반은 내장
스킬이라 파일 시스템에 실물이 없다 — 그래프에는 scope `builtin` 으로 그린다.

- **현재 세션 패널**: `buildReport()` 가 세션 로우를 안 내보낸다. 축 계산에만 내부적으로 쓴다.
  `sessions()`(scan.mjs:189)를 직접 부르는 IPC 를 하나 더 두면 목록·turn 수·마지막 기록
  시각까지 바로 온다. 세션 안 호출 흐름("메인 → general-purpose 3회")은 위임 행을 세션별로
  묶는 함수가 없어서 그것부터 써야 한다
- **채팅 패널**: 대화 저장, 모델 구독 연결, 취약점 → 채팅 전환 흐름 전체가 새 기능이다.
  분석 엔진 밖에 있다
- **Expanded(세션 접기/펼치기)**: 세션 패널이 생기면 토글과 함께 온다. 접힌 것이 기본이다
- **Config·Scanning**: 저장된 레포트를 꺼내 보는 개념이 먼저 있어야 한다(2절 참고).
  Scanning 은 `filecache.mjs` 의 `get()`/`getBatch()`(filecache.mjs:55, 82)를 진행 콜백을
  낼 수 있게 바꿔야 한다. 지금은 동기 일괄 처리라 중간값 자체가 없다
- **레포트 이전/다음 탐색**: `snapshot.mjs` 의 저장 범위를 넓혀야 한다. `condense()`
  (snapshot.mjs:44)가 축 숫자만 남기고 취약점 카드 문장·그래프·세부 분석 문장을 버린다
- **MCP 노드의 scope**: 지금은 전사의 호출 이름으로 노드를 만들 뿐 정의 출처를 안 읽어
  scope 가 `unknown` 이다. `claude mcp list` 를 부르면 된다(이름 매핑은 `[^A-Za-z0-9]` → `_`
  로 10/10 일치). **`claude mcp get` 은 환경변수를 평문으로 뱉으니 쓰지 마라**
- **그래프 라벨 겹침**: 33노드 저장소에서 왼쪽 위가 뭉친다(4.6)
- **키보드용 대체 목록**: 그래프가 캔버스라 스크린리더가 못 읽는다
- **doctor 진단**: 넣기로 정해졌지만 아직 어느 화면에도 자리가 없다. 세부 분석에 "실행 환경"
  섹션을 더하는 것이 유력하지만 이 문서가 그 결정을 대신 내리지 않는다
- **Narrow 확인**: 창을 680px 이하로 좁혀서 본 적이 없다(4.11)

**레포트 재설계(2026-09-04)가 남긴 일.** 순서가 있었다. 1·5·6·7 은 됐다. 남은 것은 2·3·4다.

1. **측정 함정 셋.** 됐다(2026-09-13, 커밋 d57d456). 한 턴 안 usage 복사, message.id 의
   파일 간 중복, `<synthetic>` 줄을 고쳤다. 위임률·캐시 적중률에 `measure: 2` 를 매겨 옛
   스냅샷과 안 견준다(`axes.mjs:155,182`). 이 저장소 위임률이 12.1% → 24.0%, 캐시 적중률이
   97.4% → 98.2% 로 움직였다
2. **위임 단위 토큰**: 서브 전사의 usage 를 위임(agentId)에 붙인다. 비용 차액의 재료다
3. **`<bash-input>` 수집**: `extractFile()` 이 user 줄을 읽게 한다. 메인 세션만, 3번 이상만
4. **새 축 셋**: 캐시 읽기 없는 턴, 한도(Codex, 전역), Codex 토큰을 캐시 적중률·위임률에 섞기
5. **`src/coach.mjs`.** 됐다. `inventory()`·`cards()`·`handoff()`(검사 23개, `test/coach.test.mjs`)가
   종류·축 정의의 문구 표(`BROKEN`/`RULE_META`)로 카드를 묶고 층에 놓고 핸드오프 마크다운을
   만든다. **CLI `--plan` 은 안 부른다** — `report.mjs` 의 `--plan` 은 여전히 `fix.mjs` 의
   `plan()` 만 쓴다. 규칙 위반 지시서는 데스크톱 앱에만 있다(`grep coach src/report.mjs` 무응답으로
   확인했다)
6. **`문제 아님` 저장.** 됐다. `loadIgnored()`/`saveIgnored()`(`src/coach.mjs`)가
   `~/.harness-bro/ignored.json`(`HARNESS_BRO_IGNORED` 로 경로를 바꿀 수 있다)을 읽고 쓴다.
   데스크톱 앱의 `report:load`·`coach:ignore` 가 쓴다. **CLI `--plan` 은 아직 안 읽는다** — 5와
   같은 이유
7. **렌더러.** 됐다. 내 하네스 섹션(요약 띠), 아쉬운 점 카드 두 열, 세부 분석 카드 여덟, 도구
   배지(글자로 시작, SVG 로고 자산은 나중에)가 `desktop/app/index.html`·`renderer.mjs`·
   `main.mjs` 에 있다

**오늘 새로 보인 것.**

- 그래프가 240px 에서 노드 라벨이 겹친다. 실측 스크린샷에서 `general-purpose`·`playwright`·
  `harness-bro` 라벨이 겹쳤다. 4.6 "33노드 저장소" 결함과는 다른 증상이다. 세로 폭을 줄여서
  생겼다
- 카드 근거 줄이 제목을 되풀이한다: `coreFact()`(`src/coach.mjs`)가 `f.title` 을 카드 제목에도
  쓰고 근거 첫 줄에도 쓴다
- 세션 패널 접기가 없어 첫 화면에서 200px 을 먹는다(세션 패널이 자리표시자 상태라 접었다 펼치는
  토글 자체가 없다, 4.0-B)
- `지시서 복사` 뒤 앱이 다시 재서 카드를 지우는 루프가 없다(위 6번 항목 및 4.0-G "끝나면" 행과
  같다). 사용자가 직접 새로고침해야 카드가 사라진다
- 패키징: `npm run dist` 는 서명 없이(`identity: null`) 아이콘도 기본값이다(`electron-builder.yml`)

아쉬운 점 카드(반복 → 규칙 → 깨진 것)와 추천 한 줄은 구현했다(4.0-D). 채팅 전환 흐름의 계약은
4.0-G 에 있다.
