# askin 랜딩페이지 브리프

이 폴더(`site/`)는 askin 의 랜딩페이지다. 이 저장소에서 새 세션을 열어 랜딩페이지를 만들 때
**이 파일을 먼저 읽는다.** 제품이 무엇인지, 무엇을 말해도 되고 무엇을 말하면 거짓말이 되는지,
어떤 파일은 건드리면 안 되는지가 여기 있다. 더 깊은 근거는 아래 "더 읽을 것"에 있다.

## 제품 한 줄

**askin 은 AI 코딩 에이전트(Claude Code, Codex)를 쓰고 있지만 하네스를 어떻게 설계해야 할지
막막한 사람에게, 프로젝트의 작업 기록을 사람 말로 해석하고 다음 하네스까지 함께 만들어 주는
데스크톱 코치다.** (원문: `desktop/design-concept.md` "한 줄 정의")

- 하네스 = CLAUDE.md·AGENTS.md 규칙, 에이전트 정의, 스킬, 훅, MCP 연결. 사용자가 에이전트에게
  적어둔 "일하는 방식" 전부
- askin 은 그 기록(`~/.claude/projects` 전사, `~/.codex/sessions`)을 **로컬에서** 읽어 재고,
  적어둔 규칙을 실제로 지키는지, 무엇이 깨져 있는지, 무엇을 손으로 되풀이하는지 보여준다
- 이름은 상황과 상대에 따라 기준을 조절한다는 뜻의 모티프다. 워드마크는 소문자 `askin`

## 누구에게

AI 코딩 에이전트를 이미 쓰는 개발자. **초보 전용이 아니다.** 중급자도 자기 하네스의 구조와
취약점을 알고 편하게 같이 고치려는 도구다. 카피에 "여기부터 해봐요" 같은 손잡이 문구를 쓰지
않는다. 권고는 "~하면 ~가 없어져요/아껴요" 한 줄 형식이다.

## 무엇을 보여주나 (화면 셋)

1. **내 하네스**: 지금 파일에 있는 정의(규칙 문서·에이전트·스킬·MCP·훅)와 전체 기록의 호출을
   요약 띠 다섯 칸과 연결 그래프로. 에이전트는 보라, 스킬은 초록, MCP 는 파랑
2. **아쉬운 점**: 카드 두 열. 층은 반복(손으로 되풀이한 명령) → 규칙(적어둔 규칙을 안 지킴)
   → 깨진 것(문서·링크가 가리키는데 없음) 고정 순서. 카드마다 근거 원문과 추천 한 줄,
   `채팅에서 고치기`
3. **세부 분석**: 주제별 카드 여덟(규칙·모델 / 관찰값 / 캐싱 / 훅 / 반복 행동 / 깨진 링크와 정의 /
   한도 / 무엇을 봤나). 값이 어느 도구 기록에서 왔는지 Claude·Codex 배지

스크린샷은 `site/assets/shots/` 에 있다.

| 파일 | 무엇 | 성격 |
|---|---|---|
| `app-current.png` | 지금 실제 앱(패키징된 빌드를 띄워 찍음). 그래프 + 옛 모양 레포트 | **실물** |
| `main.png` | 재설계한 첫 화면(내 하네스 + 아쉬운 점 카드 셋) | 목업. 값은 이 저장소 실측 |
| `details.png` | 세부 분석 카드 여덟을 펼친 상태 | 목업. 값은 실측 |
| `handoff.png` | 규칙 위반 카드에서 채팅으로 넘어가는 흐름 | 목업. 값은 다른 저장소 실측 |

목업 셋은 데이터가 진짜지만 UI 는 아직 구현 전이다. 랜딩에 쓰면 "설계"라고 말하거나
`app-current.png` 와 섞지 않는다. 지금 앱에 있는 것처럼 보이게 하면 거짓말이다.

## 이 제품이 절대 안 하는 것 (카피에서도 지킨다)

- **종합 점수·등급을 만들지 않는다.** "하네스 건강도 72점" 같은 것 금지. 축마다 자기 분모가
  있고 서로 더하지 않는다. `6/40` 처럼 분모와 함께 말한다
- **없는 숫자를 만들지 않는다.** 재는 코드가 없는 것은 화면에도 카피에도 안 쓴다.
  "모든 대화에서 같은 컨텍스트를 다시 읽고 있어요" 류의 문장은 재지 않으니 쓰지 않는다
- **잴 수 없으면 판정 불가**라고 말한다. 0% 나 "해당 없음"으로 뭉개지 않는다
- **데이터는 기계 밖으로 나가지 않는다.** 전사를 로컬에서 읽는다. 서버가 없다
- 앱은 고치지 않는다. **고치는 것은 채팅의 Claude 나 Codex** 다. askin 은 무엇을 고칠지,
  어느 파일을 건드릴지, 끝나면 무엇이 줄어야 하는지를 정확히 넘긴다

## 지금 되는 것과 아직 안 되는 것 (2026-09-13)

랜딩은 아래 사실 위에서만 말한다. 앱에 없는 것을 있는 것처럼 쓰지 않는다.

**된다**
- macOS 앱(.dmg, arm64, 서명 없음). 프로젝트 폴더를 고르면 하네스 연결 그래프와 레포트를 그린다
- 그래프: 에이전트·스킬·MCP 노드, 실제 호출 엣지(실선)와 선언만 된 엣지(점선), Codex 기록 포함
- 레포트: 준수율 축 5개(모델 명시, 잡무 모델, 하네스 활용, 스킬 선언 무결성, 훅 무결성),
  관찰값 8개(병렬 비율, 평균 갈래, 가드 차단, 위임률, 캐시 적중률, 서브에이전트 결말,
  지금 도는 세션, 턴 마무리 훅 시간), 깨진 참조 다섯 종류(죽은 경로, 없는 스킬, 깨진 심링크,
  근거 잃은 축, 모순 후보)
- CLI(`node src/report.mjs`)와 `--plan`: 고칠 것을 파일이 겹치지 않는 갈래로 갈라 지시서로 뽑는다

**설계만 됐다(구현 중)**
- 재설계한 레포트 화면(요약 띠, 아쉬운 점 카드, 세부 분석 카드 여덟)
- 손으로 반복한 명령 카드, 비용 차액(API 요금 환산), 캐시 읽기 없는 턴, Codex 한도
- 채팅 패널과 `채팅에서 고치기` 흐름. 채팅은 아직 없다
- 현재 세션 패널

## 실측 예시로 쓸 수 있는 숫자 (만든 사람 기계, 2026-09-04)

카피에 숫자를 넣고 싶으면 이 중에서 고르고 "만든 사람의 기록에서"라고 밝힌다. 새 숫자를 만들지 않는다.

- 손으로 되풀이한 셸 명령 76건 45종. 한 저장소에서 `npm run desktop` 을 7번 직접 쳤다
- 위임 40건 중 6건이 모델을 정하지 않고 부모 세션의 큰 모델을 물려받았다. API 요금 환산 월 $2
- 문맥을 처음부터 다시 쌓은 턴 1.35%(저장소별 0.32~3.88%)
- 전역 스킬 심링크 3개가 없는 폴더를 가리키고 있었고, 규칙 한 줄이 `origin/main` 을 경로처럼
  가리켰다(경로가 아니라 git ref 다. 죽은 경로 판정은 셋에 하나가 이런 거짓 양성이라 앱이 그렇게 말한다)
- 규칙 문서 2 · 에이전트 정의 1 · 쓴 스킬 7 · 쓴 MCP 5 · 훅 실행 9,638회

## 브랜드와 톤

- 보라 `#7C3AED`(밝은 화면) / `#A78BFA`(어두운 화면). **보라는 브랜드 자리에만**: 버튼, 선택 상태,
  워드마크, 그래프 에이전트 노드, 구체. 면과 글자는 중립 회색. 배경·글자·그림자에 보랏빛을
  섞지 않는다. 그래프 범주색(보라·초록·파랑) 밖의 무지개색 금지
- 밝은 화면은 순백 위에 순백 패널을 테두리와 그림자로 띄운다. 어두운 화면은 중립 먹색
- 브랜드 도상은 캐릭터가 아니라 **계속 생성되는 듯한 보라색 구체**(채팅에서 에이전트 상태를 보여주는
  오브젝트. 펫이 아니고 이름도 없다). 아이콘 파일은 아직 없다. 필요하면 그려서 `site/assets/` 에 두고
  그 사실을 보고한다
- 글꼴은 운영체제 기본(한글 UI), 경로·수치는 고정폭에 tabular 숫자. 워드마크도 같은 계열 500 무게까지
- 모션은 120~180ms 색·불투명도 전환만. 구체의 흐름은 살아 있다는 정도의 느린 변화
- 카피는 해요체, 짧은 선언, 번역투 금지. 감탄사·이모지·"not just X, it's Y" 류 금지.
  토큰과 규칙은 `desktop/tokens.md`, 컨셉 근거는 `desktop/design-concept.md`

## 참고한 UI (왜 이런 모양인가)

Lighthouse·DevTools Insights 는 통과한 것을 접는다 / Snyk·cargo audit 은 원인과 해법을 한 줄에
붙인다 / brew doctor 는 경고 앞에 "문제없으면 무시"를 먼저 말한다 / Apple Health Trends 는
관찰값에 좋다·나쁘다 없이 방향과 기간만 준다 / GitHub Autofix·Snyk·Sentry 는 사람 승인 없이
반영하지 않는다. 랜딩이 비교 대상을 언급할 필요는 없지만, 제품이 어느 결에 서 있는지는 이걸로 잡는다.

## 파일 규칙 (병렬 작업 중이라 중요하다)

- **`site/` 안에서만 만든다.** 정적 HTML·CSS·JS 로 충분하다. 빌드 도구가 꼭 필요하면 `site/` 안에
  자기 `package.json` 을 둔다. **저장소 루트 `package.json` 을 고치지 않는다**(다른 세션이 앱을
  패키징하며 같이 쓰고 있다)
- `src/`, `desktop/`, `test/`, 루트 `package.json`, `.gitignore` 는 읽기만 한다
- 배포는 Vercel 정적 사이트로 한다. `vercel` 플러그인 스킬이 이 환경에 있다. 프로젝트 루트를
  `site/` 로 잡는다. 도메인은 아직 없다. 미리보기 URL 로 충분하다
- 다운로드 버튼은 GitHub Releases 를 가리킨다(2026-09-14 에 v0.1.0 을 올렸다). `.dmg` 는 서명이
  없어 처음 열 때 우클릭 → 열기가 필요하다. 그 안내를 다운로드 근처에 한 줄로 둔다. 버전을 올리면
  링크와 파일 크기 표시를 같이 고친다. 가격·라이선스는 아직 없다. 만들어 넣지 않는다
- 화면 폭 400px 에서 깨지지 않게 확인하고 스크린샷을 남긴다. `kill-ai-slop`·`impeccable` 스킬이
  이 환경에 있다. 완성 전에 한 번 돌린다
- 커밋은 `site/` 파일만 명시 경로로. `git add -A` 금지. push 는 사용자가 말할 때만
